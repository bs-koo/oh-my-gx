# 보조 스킬·요구사항 문답 개선 보고

이번 변경은 보조 스킬 결함 13건과 후속 리뷰에서 발견한 경계를 보완하고, 조회 기능 3종 및 전체·핵심 모드의 요구사항 문답 개선을 반영한다. 작업 기준 main은 `6ef7517`이며 기존 사용자 작업과 분리한 `codex/fix-aux-skill-edges` 작업 폴더에서 준비했다.

## 반영한 개선

| 영역 | 개선 내용 | 기대되는 효과 |
|---|---|---|
| 커밋 안전·미리보기 | 이미 staged인 명시 제외 파일도 제거한다. 임시 index에서 준비하고 실제 반영 직전에 lock·HEAD·외부 변경을 재확인한다. 실패 시 부분 staging·삭제까지 원 index로 복원한다. `--preview`로 후보·제외 이유를 조회한다. | 원하지 않는 파일 포함과 실패 복구 중 작업 손실 방지 |
| Git 보호 훅 | 현재 폴더 대신 실제 `git -C` 대상을 검사한다. 여러 명령·따옴표 밖 줄바꿈을 처리하고 뒤의 보호 브랜치/SVN 차단이 앞의 경고보다 우선한다. | 다른 저장소·후속 명령을 통한 보호 누락 방지 |
| 교차 리뷰 | 큰 diff·명시 stat에서도 tracked와 untracked 파일 목록·통계를 유지하고 요약된 모든 파일의 직접 확인을 요구한다. | 신규 파일이 리뷰에서 빠지는 문제 방지 |
| 단독 GREEN | 전체 테스트·실행 설정의 목록과 지문을 비교한다. Babel·SWC·tsconfig·Gradle wrapper 등 공통 설정 판정을 재사용하며 탐색 오류도 차단한다. | 다른 테스트 삭제·skip·설정 변경으로 잘못 통과하는 경계 보완 |
| 윤문 보존·검수·이력 | 중단 실행을 포함해 run ID를 배타 예약하고 원문·라운드를 보존한다. fidelity·naturalness·최종본을 같은 run/round/지문에 결합한다. `--history`는 본문 없이 이력·상태를 조회한다. | 기존 결과 덮어쓰기와 서로 다른 초안의 검수 결과 혼합 방지 |
| 설정 탐색·진단 | 새 템플릿과 기존 등록을 구분하고 하위 스택·사용자 정의 detect까지 탐색한다. JDK 컴파일러 조건과 SVN 로컬 정보/원격 인증도 구분한다. `--inspect`는 파일 변경·설치·테스트 없이 누락 설정을 보여준다. | 복수 프로젝트 등록 누락과 도구·인증 완료 오인을 방지 |
| 정책 분석 읽기 전용 | 모델 capabilities를 표준입력으로 전달하고 dispatch 근거를 대화에 유지한다. 기존 파일 입력도 지원한다. | 읽기 전용 요청에서 모델 메타 파일 쓰기를 요구하던 충돌 해소 |
| 기술 부채 결과 분류 | 정상 빈 결과·발견과 오류·부분·미지원 스키마를 구분하고 불완전한 점수는 보류한다. 정상 npm 패키지명 `partial`·`error`·`errors`도 허용한다. | 실패한 분석을 0건/건강도100으로 표현하는 오판 방지 |
| 조사 출력 | 실행별 근거를 분리하고 확정 `--output` 경로를 저장·완료 링크·인계에 공통 사용한다. 동시 저장은 기존 파일을 덮지 않는다. | 요청한 위치와 실제 결과 위치의 불일치 방지 |
| 시각화 선택·동시 실행 | backend 선택을 전달하고 static/mermaid에서는 Archify 탐지·설치를 생략한다. 출력 잠금·고유 임시 JSON·원자적 교체로 동시 쓰기를 보호한다. | 불필요한 설치 시도와 겹친 실행의 결과 손상 방지 |
| 전체·핵심 TDD 문답 | 중요한 미정이 해소될 때까지 실제 답변·후속 질문을 반복한다. 전체는 기존 PO, 핵심 inline은 오케스트레이터가 맡는다. 새 인터뷰 에이전트·상태 기능을 추가하지 않는다. | 검증 가능한 요구사항과 실제 사용자 의도의 차이를 줄이는 문답 절차 마련 |

세 조회 기능은 조회 후 종료한다. 커밋·새 윤문·설정 변경을 시작하지 않으며, 파일 존재나 설정된 명령을 실제 검증 통과로 표현하지 않는다.

## 문답의 종료·승인 경계

명확한 요청과 같은 범위의 기존 답변·승인은 재사용한다. 답변에서 새로운 중요한 예외가 드러나면 다시 질문하며, 단순 비차단 가정은 이유를 기록한다. 종료 문구·helper 응답 기록 성공·과거 승인만으로 중요한 미정의 해소를 추정하지 않는다.

문답 해소 뒤에는 기존 PRD 승인 또는 핵심의 AC+계획 결합 승인을 수행한다. 읽기 전용·중단/재개·단독 design/implement의 요청 범위와 기존 GREEN/RED·케이스 이력을 보존한다. G-W-T 재작성·설계 검토 상한은 미정 상태의 진행 허가가 아니다.

## 검증 결과

| 범위 | 로컬 결과 |
|---|---|
| 최종 Codex 전체 | 300건 통과, 신규 문답 14건 포함 |
| 보조 스킬 신규 회귀 | 84건 통과 |
| 공통 진입·배포·예산 | 64건 통과, gx-tdd 진입 파일 19,896바이트로 20KB 미만 |
| 기존 시각화 회귀 | 85건 통과 |
| 행동 러너 mock | 30 pass, 0 fail |
| 공통 검사 | sync --check·lint 36단계·보호 훅 6그룹 통과 |
| 문서 절차 모의평가·리뷰 | 11개 시나리오와 독립 정적 재리뷰, 발견 사항 보완 후 추가 미해결 P1/P2 없음 |

검사 범위는 겹치므로 숫자를 합산하지 않는다. 실제 설치 앱·인증된 모델 호출·질문 UI는 미실행이며, 로컬 fixture·mock·문서 모의평가를 실측 통과로 대체하지 않는다. 정확도·속도·토큰 절감률을 측정한 벤치마크도 아니다.

지원 경계도 명시했다. 커밋 helper는 split/shared index와 별도 Git 경로 환경변수에서 변경 전에 중단한다. 종료되지 않은 시각화의 lock은 실행 종료를 확인한 뒤 문서 절차로 복구하며 자동 삭제하지 않는다. 의존성 결과는 문서에 선언한 도구별 스키마 범위에서 판정한다.
