# 보조 스킬 경계·복구 보완 설계

사용자는 main `6ef7517`의 보조·총괄 14스킬 감사에서 제시한 모든 문제와 경계 검증의 진행을 승인했다. 이번 범위는 수정·회귀·독립 리뷰·최종 검증이다. 기존 시각화 작업, 별도 gx-work 감사, 커밋·PR·머지는 이 작업에 포함하지 않는다.

## 목표

1. 커밋에서 명시 제외 파일을 기존 인덱스에서도 제외하고, 실패하면 부분 선택·삭제를 포함한 원 인덱스를 보존한다.
2. Git 보호 가드는 현재 cwd가 아니라 명령의 실제 대상 저장소를 검사한다. 교차 리뷰의 통계 모드에도 untracked 목록을 보존한다.
3. 단독 GREEN은 인계 대상 외 테스트의 수정·삭제·skip도 탐지한다.
4. humanizer는 중단·동시 실행의 산출물을 덮지 않고 원문·확정 장르·수정 범위를 검증 역할에 전달한다.
5. setup은 새 템플릿과 검증된 기존 등록을 구분하고 하위·추가 스택을 탐색한다.
6. lens의 읽기 전용 경계 안에서 모델 정책 계산과 근거 전달을 수행한다.
7. 의존성 조회의 오류·부분 결과와 정상 빈 결과를 구별하고, 미분석을 건강 점수 100점으로 표현하지 않는다.
8. research는 실제 저장 경로를 완료 안내·후속 명령에 재사용한다.
9. service 시각화의 backend 선택을 실제 실행까지 전달하고 공유 출력 폴더의 동시 쓰기를 보호한다.

## 접근

지시문만 바꾸면 인덱스 복구·출력 충돌 같은 기계적 규칙의 재현이 어렵다. 별도 통합 실행 엔진은 현재 구조에 비해 범위가 크다. 기존 스킬·역할·helper 구조를 유지하고, 기계적으로 판정할 부분에만 작은 helper/정책과 실행 회귀를 붙이는 방식으로 진행한다. 이는 구현자의 선택이며 새로운 제품 정책·외부 의존성을 도입하지 않는다.

## 공통 제약

- 원본 `D:/SQ/oh-my-gx`와 다른 worktree를 수정하지 않는다. 작업은 `codex/fix-aux-skill-edges`에서 수행한다.
- Python 3.10+·기존 Node/Git Bash·표준 라이브러리를 사용한다. 새 외부 패키지나 네트워크 설치를 추가하지 않는다.
- 실제 사용자 응답·읽기 전용·보호 브랜치·verify·기본 stop-at 계약을 유지한다.
- 새 기계적 검사에는 실패를 먼저 확인하고, 이후 정상·오류·중단·동시 실행을 검사한다.
- Claude 원본 역할을 변경하면 Codex 배포 역할을 generator로 갱신한다.
- 임시 소비 프로젝트/모의 검증과 실제 설치된 앱·모델·승인 UI 검증을 구별한다.

## 완료 기준

열세 발견 항목의 수정·회귀 연결을 기록하고, 기존 Codex 계약·정합성·훅·관련 모듈 회귀를 통과한다. 독립 리뷰에서 중요한 미해결 발견이 없어야 한다. 실제 앱의 대화·설치 smoke를 실행하지 않았다면 미실행으로 보고한다.

## 기능 개선 관점의 추가 범위

사용자가 기능 개선 관점도 요청했다. 이번 수정의 새 데이터·helper를 재사용하는 작은 읽기 전용 기능 세 가지를 포함한다: 커밋 포함/제외 미리보기, 윤문 실행 이력·상태 조회, 설정을 변경하지 않는 프로젝트 진단. 조회에는 새 승인·산출물 예약·설정 변경·빌드/테스트를 붙이지 않는다. 기존 기본 명령의 의미를 유지한다. 조사 업데이트 비교·기술 부채 추세·리뷰 지적 재확인은 별도 기능 후보로 시나리오·효용·구현 범위를 평가한다.
