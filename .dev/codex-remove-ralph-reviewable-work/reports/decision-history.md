# 공유 결정 이력 대조 개선

## 실제 구조를 반영한 판단

별도 소비 프로젝트를 읽기 전용으로 확인했다. `.dev/plan.md`와 과거 계획, 기능/수정별 PRD·설계·결정·BRIEF·AC·진행 상태·검증 보고가 함께 관리되고 있었다. 같은 결정 문서에서 답변이 바뀌고 후속 설계가 이를 반영하는 경우, 다른 작업의 요구사항/AC를 참조하는 경우가 있었다. 결정 시각과 Git 저장 시각은 다르며 작업 담당자와 실제 응답자도 같다고 볼 수 없다.

따라서 첫 검색 결과·최신 날짜·폴더명·Git 작성자만으로 현재 결정이나 결정자를 확정하지 않는다. 실제 업무 내용·사람 이름·비공개 원문은 이 저장소에 복사하지 않았다.

## 동작 변경

- memory·요약은 검색 단서로 쓰고, Git으로 공유한 관련 `.dev` 원문을 고정 revision·해시·경로·Git 행 번호로 확인한다. 후속 답변·개정 설계·대체/철회 여부와 적용 범위를 대조한다.
- 조회 helper는 기본 결과5개·문서200개·파일당128KiB·전체 blob8MiB의 한도를 둔다. 기본 제외 영역과 잘림·미검색 범위를 노출하며, 후보 없음이나 오류를 무충돌 판정으로 사용하지 않는다. 원문 전체를 에이전트마다 반복 전달하지 않는다.
- 새 요구와 중요한 의미 충돌이 남으면 기존 질문에 출처·시점·이유·변경 영향을 묶는다. 이미 같은 변경을 알고 답한 경우는 재사용한다. 실제 답변을 현재 작업의 기존 결정 기록에 원문·범위·변경 이유와 연결하고 과거 기록은 보존한다.
- Git 기록 기여자·기여 시각과 문서에 명시된 결정/응답자는 구분한다. 근거 없는 실제 결정자는 미확인이다. 과거 승인은 현재 개발 진입이나 실행 권한이 아니다.
- gx-work 진입, gx-context intake, TDD 문서 사전 대조 및 PRD/core·설계 재사용 이전에 조건부 연결한다. RED 격리·문서 금지·헤드리스 질문 대기를 유지한다.

## 읽기 전용 경계 검토

독립 검토에서 Git LF와 다른 Unicode 행 분리, assume-unchanged로 숨긴 작업본 변경, Git diff의 clean filter 실행을 합성 저장소로 재현했다. LF 기준 인용과 선택 후보의 제한된 bytes 비교로 보완하고 Git diff 호출을 제거했다. symlink·junction/reparse·접근 실패·관측 중 변경은 우회하지 않고 미확인으로 표시한다. bytes 비교의 개행/인코딩 차이를 의미 변화로 확정하지 않는다.

실제 소비 프로젝트의 helper 조회는 151개 후보 중 한도 내145개를 조사해 관련 구절3개를 반환했다(결과 잘림 명시). 해당 로컬 실행의 helper 시간은 약0.98초였다. 전후 HEAD·index·Git 상태 및 추적 `.dev` 1,161개 파일 해시는 같았다. 이 수치는 단일 로컬 조회이며 모델 실행·검색 완전성·사용자 이해도나 토큰 절감률을 검증하지 않는다. 이후 암묵 다운로드 금지 옵션과 누락 객체 오류 처리를 합성 회귀로 보완했다. 원시 조회 결과는 비공개 임시 경로에만 두었다.

최종 테스트·독립 재확인 결과는 [verification.md](verification.md)에 기록한다. 실제 설치 발견·모델 역할 호출·질문 UI·훅 신뢰·사용자 응답의 실세션 검증은 이전과 같이 NOT_RUN이다.
