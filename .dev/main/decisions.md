선택지:

**→** 2석: red-writer + implementer (권장) — red-writer 격리는 유지, GREEN+REFACTOR를 implementer 1석으로 통합. 태스크당 디스패치 3→2, 무결성 감시 대조 시점 절반. 테스트 수정 금지 계약과 해시 감시는 implementer에 그대로 적용.
- 1석: 원본 그대로 implementer 단독 — superpowers 원형. implementer가 RGR 전체를 수행하고 TDD Evidence(RED 실패 출력·GREEN 통과 출력)를 report 파일로 증명. 가장 빠르지만 red 격리(구현 편향 차단)를 잃음 — 감시가 증거 검증으로 대체됨.
- 3석 유지 — 현행 red/green/refactor 유지. 게이트·테스트 실행·fix loop 등 다른 항목만 수정. 구조 변경 리스크는 없지만 태스크당 디스패치와 무결성 검증 오버헤드가 그대로 남음.

**A.** 2석: red-writer + implementer (권장)

**→** RED만 격리 유지 (추천) — red-writer 디스패치는 유지하고 IMPLEMENT(GREEN+REFACTOR)는 세션이 직접 수행. 콜드 스타트 절반. "먼저 실패했다"의 증명은 남고, implementer 격리는 해시가 대신하므로 잃는 것이 없음. fix 라운드 4~5의 opus 격상 디스패치는 유지
- 둘 다 세션이 직접 — superpowers executing-plans 방식. 콜드 스타트 0. 대신 red-writer 격리가 사라져 "프로덕션 코드를 안 보고 테스트를 썼다"를 증명할 수 없음. 참조 파일 목록 검증도 무의미해짐
- 디스패치 유지, 배칭만 — 2석 구조는 그대로 두고 같은 모양의 AC 여러 개를 한 디스패치로 묶는 SDD의 배칭 규칙만 도입. 동작 변경 최소. 콜드 스타트 감소 폭은 AC 유사도에 달려 예측 불가

**A.** RED만 격리 유지 (추천)
