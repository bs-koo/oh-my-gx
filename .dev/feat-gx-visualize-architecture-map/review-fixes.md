# 코드리뷰 후속 수정

2026-10-16 사용자 요청에 따라 리뷰 3건과 관련 경계 사례를 수정했다. 이전 작업과 사용자 변경은 보존했으며 커밋·푸시는 수행하지 않았다.

## 리뷰 항목

1. **상세 앵커 충돌**: 상세 목록은 `gx-detail-`를 사용한다. Archify SVG의 `node-`와 겹치지 않는다. 개요 검색, 외부 노드, Mermaid 키보드 이동, Archify 더블클릭이 같은 상세 앵커를 사용한다. 기존 해시는 새 상세로 정규화한다.
2. **부분 갱신 상태 손실**: `domains`에는 이번 렌더 결과, `map_domains`에는 전체 맵 상태를 기록한다. 미갱신 결과는 생성 시각·리비전을 보존한 `retained`로 표시하고 개요·검색에 유지한다. 아직 생성하지 않은 도메인과 실패 결과는 정상 링크로 표시하지 않는다.
3. **SQL include 자식 요소 누락**: XML 구조를 읽어 property와 중첩 참조를 처리한다. 변수는 MyBatis의 상속·재정의 순서를 따르며, 모호한 결과는 진단으로 남긴다.

## 추가로 확인한 경계 사례

- 한글·경로 형태 ID·문자 그대로의 `%20`, 이전 해시, Enter/Space, 반복 더블클릭.
- 첫 부분 생성, 연속 부분 갱신, 선택 도메인 실패, 미생성/삭제/HTML 유실, 없는 도메인 요청.
- 이전 버전의 보존 페이지에 없는 상세 앵커를 만들지 않고 페이지로 안내.
- 다른 프로젝트에 출력 폴더를 재사용한 뒤 후속 부분 갱신해도 과거 프로젝트 HTML을 last-good로 승계하지 않음.
- 미갱신 결과의 예전 변경 배지를 이번 변경으로 집계하지 않음.
- include 변수의 상속·지역 재정의·중첩 refid, 중복 property, 미해소 참조·순환, CDATA·주석, 손상 XML·확장 한도.
- `orders<where>…</where>`처럼 태그 경계에 공백이 없는 SQL에서 가짜 테이블을 만들지 않음. where/set/foreach의 경계를 보존하고, choose의 배타 분기는 `dynamic-sql-branch` 진단으로 남김.
- 클래스와 메서드의 HTTP 매핑 조건을 Spring의 합집합 규칙으로 결합.
- 미해소 진단의 중첩 evidence에서 실제 파일·행을 표시.

## 검증

독립 검토자가 추가로 재현한 SQL 토큰 결합과 교차 프로젝트 last-good 복구 문제는 수정 후 같은 재현을 다시 통과했다. 실제 Chrome에서 BillingService 개요 검색 링크의 대상이 수정 전 SVG `g`에서 수정 후 상세 `ARTICLE`로 바뀌고 포커스됨을 확인했다. 부분 갱신 후 보존된 billing도 검색 가능했다.

실제 web 프로젝트 최종 스캔은 노드 558개·관계 912개다. 기존 857개 관계 대비 정적 근거로 확인한 연결이 늘었다. 배타 분기 내부의 테이블은 임의로 확정하지 않으므로 분기 진단 86건·동적 식별자 7건·동적 반복 2건을 결과에 남긴다. 이는 런타임 분기를 평가한 결과가 아니다.

실제 프로젝트 맵은 35개 도메인을 생성했다. Archify 검증 통과 17개, Mermaid 대체 렌더 18개이며 생성 누락은 없다. 정적 분석으로 확정하지 못한 관계 173건은 진단으로 유지했다.

Chrome의 개요·Mermaid·Archify 화면을 데스크톱과 모바일 등 7개 화면 크기/페이지 조합으로 점검했다. 페이지 가로 넘침과 브라우저 오류는 없었으며 모바일의 큰 도식은 내부 스크롤 영역에서 탐색한다. 검색→상세 ARTICLE 포커스, 도메인 간 링크, 빈 검색, 테마 유지, 개요 복귀도 확인했다.

회귀 테스트는 architecture 241개와 visualize 135개, 총 376개 항목을 확인했다. architecture 전체 실행에서는 240개가 통과하고 Chrome 자동 종료를 기다리는 테스트 1개가 시간 초과됐다. 제품 코드 변경 없이 테스트를 CDP의 검사 완료 확인·명시적 브라우저 종료 방식으로 보완했고, 해당 테스트를 포함한 viewer 13개가 재실행에서 모두 통과했다. Windows의 임시 Chrome 프로필 정리 경합에도 제한된 재시도를 적용했다. visualize 135개, Codex 리소스 동기화 검사, 정합성 린트 36개 섹션도 통과했다.

브라우저 케이스를 한 번 더 반복해 통과했고, 테스트용 headless Chrome 잔류 프로세스가 없음을 확인했다.

실행 로그·브라우저 근거는 이번 Codex 시각화 작업 폴더의 `review-fixes-*.log`(전체 실행 및 viewer 재검증 로그 포함), `review-fixed-interactions.json`, `fixed-final-browser-metrics.json`, `fixed-final-interactions.json`, `review-fixes-web-final-report.json`, `web-scan-dynamic-boundary-fixed.json`에 보관한다. 기존 사용자 변경인 `decisions.md`의 공백은 보존했으며, 그 파일을 제외한 `git diff --check`는 통과했다.
