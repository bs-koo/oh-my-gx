# Archify 페이지 레이아웃 떨림 수정

2026-10-16 사용자가 실제 프로젝트의 `domains/accessreport.html`에서 보고한 떨림을 재현하고 수정했다.

## 원인과 재현

Archify의 Adaptive Reader는 그림을 한 화면 높이에 맞추며 `--archify-reader-width`를 넓힌 뒤, 문서 전체의 세로 넘침을 보고 최소 폭으로 줄인다. GX가 추가한 탐색 영역과 상세 목록은 긴 문서를 만들므로 세로 넘침이 정상적으로 발생한다. 폭 변경이 헤더·카드의 ResizeObserver를 다시 깨워 두 계산이 반복됐다.

실제 Chrome의 1440×1000 화면에서는 1376px와 960px, 1280×800 화면에서는 1216px와 960px가 반복됐다. 120회 샘플 동안 4가지 레이아웃 상태와 120건 이상의 스타일/속성 변경을 기록했다. 모바일은 같은 반복이 없었다. 초기 검증의 오류 로그·가로 넘침 확인만으로는 시간에 따른 레이아웃 변동을 검출하지 못했다.

## 수정

공유 `viewer.css`의 `.gx-archify .container`에 문서용 `max-width:1440px`를 적용했다. 화면 폭에 따라 유동적으로 줄어들면서 한 화면 높이 맞춤 변수에 의해 폭이 반복 변경되는 경로를 끊는다. 더 구체적인 Archify의 presentation/embed 선택자는 기존 화면 모드를 유지한다. 외부 Archify 패키지나 원본 SVG는 변경하지 않았다.

실제 프로젝트 `.dev/architecture/`의 Archify 페이지 17개도 공유 스타일 블록을 교체해 수정했다. IR·노드·관계·생성 시점은 변경하지 않았다. 재생성 시에는 수정한 템플릿이 사용된다.

## 확인

- 동일 Chrome 측정에서 데스크톱·노트북·모바일 각각 120회 샘플이 1개 레이아웃 상태로 유지됐고 스타일/속성 변경은 0건이었다.
- viewer 테스트 13개 통과. 실제 브라우저 검사에는 폭 변동 재현 조건, 모바일 유동 폭, presentation/embed 우선순위를 포함한 11개 단언이 들어간다. 최초 실행에서 Chrome 탐색 시간 초과 1건이 있었고 단독 재실행은 통과했다.
- UI detector 결과 `[]`, Codex 리소스 동기화 검사 통과. 린트 결과는 `flicker-lint.log`에 기록한다.
- 전후 화면·측정·테스트 로그는 이번 Codex 시각화 폴더의 `flicker-before-*`, `flicker-after-*`, `flicker-viewer-recheck.log`에 보관했다.
