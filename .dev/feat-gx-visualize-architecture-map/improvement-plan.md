# gx-visualize 개선 반복 1

2026-10-16 사용자의 “모두 수정 시작해줘” 및 skill-creator 지정에 따라 기존 감사 D01–D15를 구현한다. 기존 decisions.md와 설계 §5.9의 작업 내용은 보존한다. 커밋·푸시는 이 작업에 포함하지 않는다.

## 요구사항과 검증 기준

- D01–D03: 정적 코드에서 확인한 호출만 calls로 표시한다. 주입 관계는 depends_on으로 구분한다. 다중·무인자·path 매핑, 필드 가시성, 선언된 구현 인터페이스를 처리한다. SQL의 주석·리터럴·CTE·함수는 테이블에서 제외하고 절별 읽기/쓰기를 구별한다. 해소하지 못한 입력은 진단으로 남긴다.
- D04–D05: 전체 IR과 도메인 간 관계를 보존한다. 개요에서 대표 진입점과 관계를 보고 검색·도메인 상세로 이동한다. 설명은 실제 식별자와 근거에서만 만든다.
- D06: service의 결정적 실행 명령, 다른 네 뷰의 입력 계약, complete 단계 제안 흐름을 문서·테스트에서 일치시킨다.
- D07–D10: 사람이 읽는 이름 우선, 내부 ID는 접기, 노드·관계·근거 탐색, 공통 돌아가기와 검색, 작은 화면에서 읽을 수 있는 그림/목록, 테마 저장, 한국어 관계·계층 범례를 제공한다.
- D11–D12: 실행 manifest를 현재 결과의 정본으로 사용한다. 실패·빈 스캔에 과거 성공을 현재 성공으로 제시하지 않는다. HTML·도식 자산 유무에 따른 실제 표시 능력을 기록한다. 과거 정상 파일은 last-good로 명시한다.
- D13–D15: 누락 이유와 파일·대상을 표시한다. 삭제만 있는 변경도 요약한다. Git 최상위 경로와 모듈 상대 경로를 맞추고 비웹 origin에서 원격 근거를 만들지 않는다.

## 구현 계약

기존 scan → 전역 IR → 도메인 분할 → 렌더 구조를 유지한다. IR의 추가 필드는 하위 호환적으로 도입한다. 외부 노드에는 external_domain, 원래 심볼에는 symbol을 둔다. 도메인 간 엣지는 양쪽 상세에 경계 노드와 함께 보존하며 missing_inputs로 세지 않는다. meta.navigation에 domain과 domains 목록을 두고, meta.changes에 도메인별 removed/removed_edges를 둔다. run-manifest.json은 현재 실행의 domains와 실패 원인을 기록한다.

## 구현 순서와 소유 파일

1. 분석 정확성: scan_entrypoints.py 및 전용 분석 회귀 테스트. (독립)
2. 상세 화면: render_fallback.py, render_archify.py, to_archify.py, templates 및 전용 UI 회귀 테스트. (독립, 기존 IR 필드와 위 추가 필드 사용)
3. 통합: build_map.py, split_domains.py, build_index.py, changes.py, 스킬·참조·가이드·계약 테스트. (1·2의 인터페이스를 유지하며 통합)
4. 회귀 테스트, lint/sync 검사, 이전/개선 스킬 동일 프롬프트 평가 및 skill-creator 정적 평가 뷰어 생성.

## 평가 시나리오

1. Spring 매핑·주입·메서드 호출과 SQL 복합 쿼리가 있는 프로젝트의 서비스 맵 생성.
2. 두 도메인이 연결된 프로젝트에서 개요 → API → 외부 서비스 → 근거 탐색.
3. 정상 생성 이후 실패·빈 입력·삭제 전용 변경 시 최신 상태와 실제 제공 화면 확인.

기존 스킬은 사용자 시각화 작업 디렉터리의 gx-visualize-workspace/skill-snapshot에 보관했다. 자동 검증과 실제 에이전트 평가를 구분해 보고하며, 시간·토큰은 관측된 값만 기록한다.
