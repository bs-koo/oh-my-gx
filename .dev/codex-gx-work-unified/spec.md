# gx-work 통합 작업 명세

사용자가 2026-11-04 대화에서 공통 진입점 gx-work, 비TDD gx-dev 제거, gx-context·gx-tdd 사용성 개선, 불필요한 전체 테스트 반복 축소, 토큰 효율 분석 및 PR 생성을 요청했다. 이 문서는 그 요청과 앞서 합의한 방향을 실행 가능한 범위로 기록한다.

## 수용 기준

1. gx-work 하나가 이해·계획·개발·재개·상태 의도를 처리하고 요청한 종료점을 보존한다. 계획·이해 요청에서 브랜치 전환·stash·pull·제품 코드 작성이 발생하지 않는다.
2. gx-dev 스킬과 비TDD 개발 경로를 제거한다. 공통 Codex 실행 규약·역할은 gx-work로 옮기며 Claude·Codex 설치 경로가 끊기지 않는다.
3. gx-context는 최신 main의 원장·작업계획 동기화 기능을 보존하고, 이미 근거가 있는 사실을 재인터뷰하지 않으며 다음 단계에 결정과 문서 경로를 전달한다.
4. gx-tdd는 정규화한 계획·handoff를 받아 기존 요구사항·설계 결정을 재사용한다. RED 격리, 테스트 불변, 승인된 범위, verify 지문 및 보호 브랜치 게이트는 유지한다.
5. 테스트는 변경 영향과 명시 매핑을 기준으로 선택한다. 알 수 없는 코드·공통 설정·의존성 변경은 전체 검사로 확장하고 이유를 남긴다. 같은 실행·동일 코드·동일 명령·동일 설정·동일 범위의 성공 증거만 재사용한다. 실패·0건·변조 로그는 재사용하지 않는다.
6. 테스트를 포함하는 빌드와 별도 테스트를 중복 실행하지 않는다. baseline·review·complete·commit이 같은 증거와 선택 규칙을 따른다.
7. 스킬은 짧은 진입 안내와 조건부 참조로 구성하고, 보고는 파일 경로·결정·변경 요약 중심으로 인계한다. 개선 전후 지시문 크기와 중복 실행 경로를 측정하되 실제 토큰·시간 절감률을 추정으로 주장하지 않는다.
8. 관련 회귀 검사·리소스 정합성·보호 조건을 확인하고 한국어 변경 설명과 검증 범위·제한이 있는 PR을 생성한다. 머지는 수행하지 않는다.

## 권한과 범위

구현·관련 수정·커밋·push·PR은 사용자가 요청했다. 초기 인터뷰와 반복적인 진행 여부 질문은 생략한다. 기존 승인 상태를 꾸며 만들지 않으며 소비 프로젝트에서 필요한 실제 결정·승인은 계속 기다린다. 원본 작업 폴더의 미커밋 시각화 변경은 별도 worktree로 보호한다.

## 기존 개선 논의의 처리

압축 이후 규칙 복원·리뷰의 근거 부족 구분·원인 조사·실행 식별·근거 기반 효율 보고는 이번 통합의 실행/인계 계약에 반영한다. 전체 세션 원문을 자동 수집하거나 외부로 전송하는 진단 기능은 만들지 않는다. 제공 가능한 로그·파일 크기·명령 실행 증거를 분석한다.
