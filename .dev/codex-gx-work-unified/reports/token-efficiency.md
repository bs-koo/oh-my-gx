# 지시문·계획 인계 효율 검토

비교 기준은 `43acaee`이고 현재값은 이 보고서의 측정 스크립트를 마지막 실행한 worktree다. **문장 수나 길이만으로 최신 모델의 성능 하락을 단정하지 않는다.** 실제 개선 대상은 무관한 지시의 상시 로드, 같은 계획·출력의 반복 전달, 서로 다른 실행 경로의 충돌이다. 필수 안전 조건·사용자 의도·실제 테스트 증거는 보존한다.

## 이번 변경의 소비 경로

- gx-work는 작은 진입문에서 사용자 의도·현재 진행 상태·종료점을 보존한다. 이해만이면 실행 상세를 읽지 않고, 계획이면 planning만, 실행이면 handoff와 gx-tdd를 추가로 읽는다. plan-only에 Git 준비나 테스트를 시작하지 않는다.
- gx-tdd는 역할·phase 소개를 `roles-and-phases.md`로 옮겼다. 이 파일은 필수 참조이므로 **main 파일이 작아진 만큼 전체 입력이 감소했다고 해석할 수 없다.** 아래 필수 계약 부분합에서 실제 차이를 별도로 보인다. 오래된 gx-dev 차별점 표는 제거했다.
- 후속 변경에서 개발 문서 정합성을 기본화하면서 gx-tdd에 문서 수명주기·최소 연결 계약을 추가했다. 이 기능은 진입 지시문을 늘린다. 관련 자료의 해시·구조는 helper가 처리하고 모델에는 현재 FR/W·관련 절·변경 요약만 주어 반복 원문 전달을 줄인다. 순 토큰·시간 절감 여부는 실제 실행 측정 전 확정하지 않는다. 문서 정합성 기능의 추가 비용을 길이 감소로 포장하지 않는다.
- gx-lens는 조회와 영향 분석의 참조를 나누고 조회 후 강제 후속 질문을 없앴다. 영향 분석도 관측된 경계에 따라 직접 또는 필요한 역할만 사용한다. 위치·지문 helper는 의미·실행을 증명하지 않는다. 새 문맥의 조회 probe 1회와 파일 회귀는 확인했지만 구버전 모델 A/B·실제 설치 발견·토큰 비용은 측정하지 않았다.
- gx-cross-review는 codex/native advisor와 fallback, 발견 처리, 결과 양식을 분리했다. 선택되지 않은 advisor·발견이 없는 경우의 수정 질문·산출물이 있는 경우의 fallback 지시는 읽지 않는다. 자동 수정 금지 게이트는 main 앞부분에 유지했다.
- gx-setup은 프로젝트 타입, git/SVN 인증, Google Chat 설정을 분리했다. 선택한 VCS 인증만 읽고 이미 Chat 설정이 있거나 SVN이면 알림 상세를 읽지 않는다. 사용자 질문·권한 보존·기존 인증 사용 조건은 원문 계약을 유지한다.
- gx-humanizer는 한국어/영어 치트시트와 strict 검증, 블로그/SNS voice 예시를 분리했다. 입력 언어·모드·문서 유형에 필요한 참조만 읽는다. 입력은 데이터라는 조건, 원본 무변경·산출물 경로 가드, 변경률 상한과 strict의 의미 보존 조건을 보존한다.
- gx-visualize의 service 맵 실행·도메인 분할·표시·보고 계약은 service 뷰만 필수로 읽는다. 다른 뷰가 큰 service 설명을 읽지 않아도 라우팅·검증·폴백·실패 게이트를 main에서 따른다. gx-verify 지문 계산은 git 통과 단계에서 반드시 읽는 참조로 옮겨 main 예산을 지킨다. 이 경로의 전체 소비량이 줄었다고 주장하지 않는다.

계획 인계는 normalized plan과 handoff 파일을 한 번 저장하고 현재 태스크 ID·필요한 섹션·파일 포인터로 진행한다. `units[]`를 gx-tdd 기존 RGR 태스크에 직접 매핑하고, PRD/설계/현재 태스크를 매번 새 계획으로 분해하지 않는다. 부모 문맥에 전체 미래 계획·전체 diff·이전 태스크 보고서를 누적하는 관행을 줄일 근거다. 각 RED 입력은 해당 AC·공개 인터페이스·테스트 의도/경계로 한정하고 구현 본문을 전달하지 않는다. 유용한 자료가 누락되면 원문 절을 다시 읽으며 무작정 축약하지 않는다.

## 경로별 정적 크기 비교

## 검증과 다음 판단

`test_gx_work.py`는 임시 Git 저장소의 미커밋 데이터와 state가 이해/계획/상태 조회에서 바뀌지 않는지 확인한다. 기존 run-id·목표·종료점 보존, 외부 계획의 자체 승인 무시, 누락·충돌·의존성 순환, context 인계 보존을 검증한다. 임시 설치 경로로 7개 스킬을 복사하여 실제 Read/이동된 script 포인터와 20KB main 예산도 검사한다. `test_codex_resources.py`의 실제 skills-only export 및 `test_codex_skill_layout.py`의 계약 검사를 함께 실행했다.

helper는 계획에 적힌 테스트 명령을 실행하거나 셸로 넘기지 않는다. route는 고정 argv의 `git branch --show-current` 읽기 조회만 사용하고 Git 변경·임의 명령 실행·파일 쓰기는 없다. `--approval-source`는 하네스가 확인한 실제 사용자 근거이며 helper가 진위를 인증한다고 주장하지 않는다.

다음 실측은 같은 요청·소스 기준으로 task 성공률, 의도·범위·게이트 준수, 재질문 수, 테스트 실행 수, 사용 토큰과 지연을 비교해야 한다. 이번 로컬 데이터·설치 검사만으로 자동 발견·실제 모델 성능·실제 비용 절감을 입증하지 않는다.
