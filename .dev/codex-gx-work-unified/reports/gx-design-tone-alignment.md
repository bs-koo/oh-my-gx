# GX Design 기준 이름·소개 문구 정렬

기준: oh-my-gx HEAD `53f6e58`, gx-design main `b8bbb84`. `git ls-remote origin refs/heads/main`으로 gx-design의 로컬/원격 일치를 확인했다. 참조 개편은 [d100f38](https://github.com/bs-koo/gx-design/commit/d100f38)이며 수행 작업·결과 중심의 제목과 설명, 공개 안내의 합니다체·스킬 계약의 한다체를 적용한다.

## 반영

- 사용자 정정에 따라 브랜드·설치 화면·README·Pages의 이름을 **oh-my-gx**로 유지한다. 직전 GX Development 표시는 말투 정리를 이름 변경까지 넓힌 해석이어서 원복했다. 기존 18개 `gx-*` 호출 ID와 저장소/홈페이지 URL은 보존한다.
- 공통 소개: **요구사항 분석, 구현, 코드 리뷰와 검증을 지원하는 개발 워크플로.** Claude/Codex 매니페스트·마켓플레이스·README·사이트 소개에 적용했다.
- 복잡한 내부 동작 명칭 대신 작업을 설명한다. `개발 워크플로 연결 → 개발 작업 진행`, `기술 부채 분석 → 기술 부채 진단`, `문체 교정 → 문장 교정`, `개발 산출물 시각화 → 구조·흐름 시각화`로 정리했다.
- 18개 SKILL의 description·첫 H1을 정리하고 README/Pages 과업명을 맞췄다. H1이 없던 4개에는 제목만 추가했다. 공개 안내는 합니다체, 모델용 조건과 실행 지침은 한다체를 유지한다.
- 단독 단계·시각화의 명시 요청, Ralph 개발 요청 라우팅과 내부 전용 반복, 교차 리뷰 표현, 요구사항·작업 분할의 자동 선택 경계를 보존했다.
- 설치 안내에서 표시명과 실제 패키지의 관계를 설명한다. CLAUDE.md의 기존 정확성 보장 표현은 등록 자료의 참조·확인 가능한 검증 범위로 구체화했다.

## 확인

- 공개 문서/HTML 4개 + 배포 경로/진입 예산 4개 + context description 트리거 1개 통과. 정합성 린트 36절·생성물 검사·공백 검사 통과.
- PyYAML로 18개 frontmatter를 읽고 HEAD와 대조했다. `description` 외 메타데이터와 첫 H1 외 본문이 동일하며, 호출 ID·allowed-tools·질문·게이트·절차 변경은 없다. 모든 SKILL 진입문은 20KB 미만이다.
- 매니페스트의 설치 ID·버전·도구/훅·URL·author·키워드는 유지했고 소개 문구의 일치를 확인했다.
- 별도 Chrome 세션의 1440×1000·375×812에서 표시명, 페이지 폭, GitHub 버튼 위치, 내부 앵커와 설치 명령을 확인했다. 화면을 직접 검토했고 최종 문구에서도 같은 검사를 수행했다. 임시 결과는 `D:/Temp/gx-tone-pages-final-v2-20261104/`에 있으며 브라우저를 종료했다. 최종 문구 첫 화면 캡처는 도구 timeout으로 끝났고 새 임시 프로파일로 재확인하여 통과했다. 제품 코드·테스트 제한시간은 바꾸지 않았다.
- gx-design 조사 담당자가 공개 문구를 독립 검토했다. 표시명·설치 이름 연결, 과도한 성과 보장, 묶음 스킬 카드 제목의 제안을 반영했다. 확인한 범위에 남은 명명/설치 호환성 충돌은 없다.

YAML description 합계는 1,768 → 1,598 Unicode 문자다. 이는 문구 정리 수치이며 토큰/비용 절감 실측이 아니다. 최신 정적 표는 token-efficiency.md를 따른다. 실행 로직을 바꾸지 않은 문구 정비이므로 로컬 전체 기능 검사는 반복하지 않았다. 실제 설치된 메뉴 표시·자동 스킬 발견은 이번 검사로 검증했다고 주장하지 않는다. PR #97의 최신 CI를 최종 원격 근거로 사용하며 Pages 배포는 main 병합 후 기존 workflow를 따른다.

## 브랜드 정정

브랜드 변경은 사용자 요청 범위를 넘긴 해석이었다. oh-my-gx 표시명을 복원하고 작업 중심 설명·스킬 제목과 기능은 유지한다. 새 브랜드로 표시한 PR 제목·본문도 정정한다. 이전 두 크기의 화면 검사와 이번 짧아진 이름의 정적/공개 문서 검사를 구별하며, 표시명 정정을 위해 실행 로직·테스트는 바꾸지 않는다.
