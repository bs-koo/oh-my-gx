# 문서 정합성 기본화·gx-lens 후속 개선

기준 HEAD: b6542ee. 사용자 승인 범위는 개발 전후 context/원장/작업계획 정합성 기본 적용과 gx-lens 현대화이며 기존 PR #97에 반영한다.

## 전후 비교

| 항목 | 이전 | 변경 |
|---|---|---|
| 개발 전 문서 | context 참조와 W 연결이 일부 경로에서 선택적 | gx-work·직접 TDD·core·재개·부분 phase·Ralph의 관련 문서 대조 공유 |
| 최초 개발 | context/계획 없이 착수 가능 | 이번 요청의 최소 FR·AC·W 연결. 전체 인터뷰·스캔·문서 묶음 생성은 강제하지 않음 |

읽기 전용·명시 문서 금지·기존 승인/종료점·RED 격리·verify 지문·보호 게이트를 유지한다. 새 PR URL은 .dev 전달 기록에 두며 최종 verify 뒤 context에 쓰지 않는다. 이번 실행이 만든 미검증 ✅만 로컬 journal/파일 해시를 확인한 후 조건부 원복한다.

## 마지막 경계 재조사

독립 검토자가 수정 종료 후 helper와 직접/부분/재개/Ralph 완료 경로를 검토했다. 다음 결함을 실제 임시 fixture 또는 새 문맥 probe에서 확인한 뒤 보완했다.

- 다른 branch가 같은 slug를 쓰면 W/run이 달라도 state 덮어쓰기를 차단한다.
- 폐기 FR은 착수를 막고, 기존 완료 FR의 버그 수정은 과거 ✅/PR을 보존한다.
- requirements.path는 프로젝트 경계와 해당 도메인의 실제 원장 경로를 확인한다.
- 같은 run/branch라도 다른 W로 조용히 전환하지 않는다. state 기록 전에 기존 연결을 검사한다.
- stdin의 한글·기본 코드페이지 차이, 이전 전체 보고서/snapshot, 선행 0·거대 범위, 외부 링크, 잘못된 재사용 입력을 검사한다.
- lens probe의 잘못된 Windows `/D:/...` 링크 출력을 발견해 실제 절대경로 사용 지침을 보완했다. Codex 질문 도구의 구체적인 이름도 읽기 전용 예외와 함께 명시했다.

마지막 W 전환 수정 후 독립 검토자의 두 위치 재확인 결과, 검토 범위에 미해결 P1/P2는 없었다. 이는 무결점이나 실제 설치 전체 동작의 보증이 아니다.

## 검증 근거와 한계

- development helper: 최초 실패 재현을 거쳐 최종 실제 fixture 23개 통과. installed helper/subprocess, 파일 불변, symlink, 스냅샷, 경로·상태 충돌을 포함한다.
- lens: 실제 파일 helper와 스킬 계약 15개 통과. 별도 새 문맥 조회 probe 1회에서 `<100`/`≤100` 차이·운영 설정 미확인·후속 질문 없는 종료를 확인했다. 이전 버전 A/B는 수행하지 않았다.
- 관련 계약: context 27개 + 배포 예산/경로 4개 + 문서 수명주기 7개, 총 38개 통과. 공개 문서/HTML 4개 통과.
- Codex 전체 계약은 통합 시 한 번 실행했다(259개). 변경하지 않은 runner의 Windows 자식 프로세스 종료 검사에서 1회 실패했고 해당 단독 검사 재실행은 통과했다. 첫 실행은 전체 성공으로 보고하지 않는다. 컴포넌트 재검사·최종 CI는 아래 통합 결과에 기록한다. 검증을 통과시키기 위해 timeout/test/runner 소스를 바꾸지 않았다.
- 정합성 린트 36절·Codex 생성물·공백 검사 통과. 이전 Ralph push 요구 린트는 새 계약에 맞게 최종 리뷰/문서 인계·조기 W 완료/계획 push 금지를 확인하도록 바꿨다.

정적 측정에서 lens 조회 지시문 부분합은 26,856 → 25,744 bytes다. 반면 TDD 필수 진입·문서 연결 부분합은 새 정합성 기능을 포함해 65,906 → 85,965 bytes로 늘었다. helper 코드와 snapshot은 모델 입력으로 반복 전달하지 않는다. 실제 순 토큰·지연·비용 절감률, 구/신 모델 A/B, 설치된 2.0.0의 자동 발견·질문 UI·모델 배정·hook 신뢰는 미측정이다. 전체 스킬의 최적 문장 수를 주장하지 않는다. 세부 파일 목록은 token-path-metrics.json을 따른다.

README·Codex/사용 가이드·Pages 소스·CHANGELOG도 새 흐름에 맞췄다. 이번 문구 변경은 HTML 계약으로 확인했고 이전 단계의 화면 검사와 구별한다. Pages 실제 배포는 main 병합 후 기존 workflow가 수행한다.
