# 1.37.0 대비 2.0.0 개선과 최종 경계 검사

비교 기준은 작업 시작 시 main `43acaee`(1.37.0)이고 변경은 PR 97이다. 소스의 동작·검사 결과와 정적 지시문 크기를 비교한다. 실제 설치된 모델의 품질·토큰·지연 A/B는 수행하지 않았다.

이 문서는 초기 개선 단계의 비교 기록이다. 이후 반영한 GX 역할별 총괄·TDD 진입 확인·구현방법 선택, gx-work 사용 예시와 18개 스킬의 최종 전후 비교는 [최신 개선 보고](adaptive-orchestration.md)를 따른다. 최신 지시문 크기는 [재측정 보고](token-efficiency.md)에서 확인한다.

## 사용 흐름

| 항목 | 이전 | 변경 후 | 사용자에게 달라지는 점 |
|---|---|---|---|
| 시작 명령 | gx-dev/gx-tdd와 실행 모드·프로파일을 선택 | gx-work에서 이해·계획·개발·상태·재개를 연결, 개발은 gx-tdd로 통일 | 요청을 업무 흐름으로 옮기는 선택을 줄인다 |
| 요청 범위 | 전체 개발 사이클 중심, 착수·재개 기록에 Git 부수효과 가능 | 기본은 verify까지, commit/pr은 명시한 종료점에서 수행. 이해·계획은 실행용 Git 준비와 분리 | 계획만 요청했는데 개발·커밋·push로 넘어가는 일을 막는다 |
| 기획·계획 인계 | 문서·결정이 있어도 phase별 재작성·반복 확인 가능 | 정규화 plan과 인계 파일로 근거·결정·승인·run-id·종료점·현재 태스크를 보존 | 아까 한 설명과 승인을 다시 전달하는 부담을 줄인다 |
| gx-context | 모드별 고정 확인과 코드 사실/미래 요구사항 혼동 가능 | 근거가 있는 사실은 재질문하지 않고, 실제 미정·충돌만 확인. 관측 코드를 신규 FR로 발명하지 않음 | 질문 수를 줄이면서 결정 출처를 남긴다 |
| 작업계획표 | 1.37에서 이미 모든 모드의 자동 갱신 도입 | 기존 자동 갱신을 유지하고 공통 parser가 모든 원장의 누락·중복·폐기·완료 후보와 의존성에 따른 ready/blocked를 검사 | 원장과 계획의 불일치·잘못된 다음 작업 추천을 발견한다. ID·진행·PR 기록은 보존한다 |
| 태스크 테스트 | focused 미등록/오류이면 전체 test로 전환, 이후 태스크에서도 반복 가능 | 실제 runner와 현재 파일만의 명령을 조립. 미지원이면 설정을 보완하거나 명시적으로 선택, 헤드리스는 차단 | 전체 테스트가 태스크마다 조용히 반복되는 경로를 줄인다 |
| 경계 검증 | 착수 전체 기준선·완료 전체 회귀·커밋 빌드가 반복될 수 있음 | 영향 범위를 계획하고 같은 실행·트리·config·command·cwd·scope·log의 성공 증거만 재사용. buildOnly 분리 | 검증 결과가 유효한 동안 같은 작업을 중복 실행하지 않는다 |
| 지시문 | 선택하지 않은 advisor·인증·언어·strict·뷰 설명도 main에서 읽음 | 필요한 분기만 읽는 참조로 나누고 전체 SKILL 진입문에 20KB 미만 운영 예산 적용 | 무관한 지시의 상시 로드를 줄이고 필요한 규약은 파일에서 다시 확인한다 |

범위가 불명확하거나 공통 설정·의존성이 바뀌면 전체 검사로 확장한다. 실패·0건·변조·다른 실행의 증거는 재사용하지 않는다. 필수 승인, RED 격리, 테스트 불변, 보호 브랜치, verify 지문은 유지한다.

## 수치로 확인한 범위

아래는 token-efficiency.md가 정의한 **해당 경로의 지시문 부분합**이다. 공통 runtime·역할 본문·코드·도구 결과·모델 출력은 제외한다. 전체 입력 토큰이나 실행 비용 절감률이 아니다.

| 경로 | 이전 → 현재 UTF-8 byte | 변화 |
|---|---:|---:|
| 교차 리뷰 native, 수정 처리 없음 | 35,425 → 24,795 | -30.0% |
| 한국어 humanizer audit/rewrite 기술문서 | 23,984 → 14,676 | -38.8% |
| 비서비스 시각화 진입부 | 25,271 → 12,949 | -48.8% |
| TDD 직접 진입 필수 계약 | 65,906 → 65,135 | -1.2% |
| verify main+필수 지문 계산 | 17,759 → 20,980 | +18.1% |

따라서 모든 경로가 크게 짧아졌다고 볼 수 없다. TDD 필수 계약은 대부분 유지했고 verify는 영향 선택·증거 확인 때문에 늘었다. 기대 효과는 선택 기능을 덜 읽고, 계획을 덜 재작성하며, 유효한 검증을 덜 반복하는 데 있다. 실제 토큰·시간 개선율은 같은 요청·저장소·모델로 따로 측정해야 한다. 연구 원문과 모든 스킬의 byte/문자/행/근사 문장 수는 [token-efficiency.md](token-efficiency.md)에 있다.

## 작업 완료 후 다시 수행한 경계 조사

기존 CI의 성공만으로 판단하지 않고 임시 Git·SVN형 디렉터리·JSON·Markdown fixture에서 새 입력을 구성했다. 원본 checkout의 진행 중 시각화 작업은 건드리지 않았다. 전체 저장소 테스트를 수정마다 다시 실행하지 않고 각 소유 범위의 검사와 새 재현을 사용했다.

다음 8종을 재현한 뒤 실패하는 회귀를 먼저 추가하고 수정했다.

| 재현한 경계 | 수정 후 |
|---|---|
| 넓은 source 매핑이 변경 테스트 자체를 대체 | 변경·필수·매핑 테스트 합집합을 실행 범위로 유지 |
| `-`로 시작하는 테스트 경로를 옵션으로 해석 | focused·선택·related 명령에서 `./`를 붙인 파일 인자로 전달 |
| 테스트·source·공유 설정·프로젝트 root가 외부 symlink로 이탈 | helper가 소비하는 변경/필수/선택 경로의 실제 대상을 확인하고 차단. 전체 파일 스캔은 추가하지 않음 |
| 작업계획표 제목·AC의 escaped pipe를 열 구분으로 오인 | 역슬래시 홀짝을 반영해 셀을 분리. [GFM 표 규약](https://github.github.com/gfm/#tables-extension-)의 escaped pipe·콜론 정렬·가변 dash를 확인 |
| 표 구분선이 없으면 첫 요구사항/작업을 조용히 누락 | 명시 오류와 `ready=[]`로 차단 |
| 같은 작업의 `FR-1~2,FR-2`를 작업 간 중복으로 오인 | 행 내부 참조만 순서대로 중복 제거. 서로 다른 작업의 중복 배정은 계속 차단 |
| SVN의 머신별 활성 포인터가 없으면 기존 작업을 찾지 못함 | 후보 1개는 기존 실행·보호 조건을 복원하고, 여러 개면 선택 전 읽기 전용으로 대기 |
| 1,100단위 유효 계획이 재귀 한도를 넘어 JSON 없이 종료 | 반복 스택으로 검사. 큰 정상 계획·순환 모두 기존 구조화 결과를 반환 |

스킬·helper 수정 종료 뒤 관련 입력을 다시 실행했다. 진입 쪽은 SVN 보완 후 관련 28개, 대형 계획 보완 후 영향받는 정규화 12개가 통과했다. 컨텍스트는 27개와 수정 관련 임시 입력 5개·wrapper 4개가 통과했고, 최초 입력을 포함해 34개 고유 시나리오를 관찰했다. 테스트 선택은 최종 코드의 관련 24개와 임시 선택 입력 22개가 통과했다. 기존 31개 검사와 proof 입력 6개의 근거를 재사용하고 전체를 다시 반복하지 않았다. 배포/개행 7개도 이번 재점검에서 통과했다.

별도 검토자가 최종 변경 내용을 다시 읽고 기존 pipeline·Ralph lock·종료점·원장 보존과 오류 경로를 대조했으며 남은 중요 회귀는 발견하지 못했다. 이는 검사한 범위의 결과이며 실제 설치 UI·자연어 자동 발견·SVN 서버 연동·소비 프로젝트 runner 성능까지 검증했다는 뜻은 아니다. 원시 실행 증거는 같은 작업의 무시되는 `logs/edge-*-20261104.log`에 보관한다.

이 단계(문서 수명주기·lens 후속 개선 전)의 CI 대상은 Codex 계약 250개와 진입/배포 34개·컨텍스트 27개·테스트 계획 38개로, 플랫폼별 349개였다. 이후의 문서 정합성 기본화·lens 개선과 마지막 경계 재조사는 [후속 비교 보고서](document-lens-final.md)에 기록한다. 원격의 최종 성공 여부는 PR 97 최신 checks를 따른다.
