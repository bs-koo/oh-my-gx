## PR 97의 Windows CI 후속

첫 원격 검사에서 공통 정합성과 Linux 계약은 통과했고, Windows는 새 gx-work 역할 경로에 이전 gx-dev의 LF 속성이 적용되지 않아 배포 리소스 검사에서 멈췄다. `.gitattributes`의 경로를 수정하고 실제 `git check-attr`로 role/index의 LF를 확인했다. sync 검사는 CRLF쌍만 LF로 정규화하고 writer는 LF를 유지한다. BOM·lone CR·추가 빈줄·본문/설정/잔여 역할 차이는 계속 실패한다. 신규 회귀 2개와 기존 내용 drift 보호 1개가 통과했고 실제 `--check`도 통과했다. 세부 RED→GREEN 근거는 [ci-line-endings.md](ci-line-endings.md)에 있다. CI Python은 UTF-8을 명시한다. 최종 원격 결과는 PR checks를 따른다.

이 보완 뒤 canonical 지문은 `d666372:ac2d9d34f743`이며, 같은 코드의 검증 근거를 보존했다.

## GX 역할을 유지하는 적응형 총괄

최신 역할·사용 예시·18개 스킬의 전후 비교는 [adaptive-orchestration.md](adaptive-orchestration.md)에 있다. gx-work는 필요한 스킬과 다음 단계를 선택하며, context의 도메인/FR/W 관리와 TDD의 PRD/설계/T계획을 분리한다. 실제 TDD 진입 응답을 확인하고, TDD 안에서는 계획 검토와 구현 방식 선택을 함께 기록한다.

Codex 통합 263개는 로컬에서 한 번 실행했다. 기존 질문 수정 대기 문구 계약 1건이 실패하여 의미를 유지한 문구를 복원했고, 해당 질문 모듈·새 게이트·helper 34개가 통과했다. 매 수정마다 전체 집합을 반복하지 않았다. 마지막 변경은 helper 54개(신규 20개 포함), 적응형 게이트 4개, 공개 문서 4개로 확인했다. 신규 사례는 RED 재현 후 수정했다. 배포 생성물 검사, 정합성 린트 36절, 보호 hook, 공백 검사는 통과했다. 최신 소스의 전체 플랫폼 결과는 이 변경을 push한 PR CI를 따른다.

수정이 끝난 뒤 요청받은 백그라운드 엣지 감사 1회를 별도 읽기 전용 에이전트로 수행했다(25파일). 계획 전용 handoff의 phase 루프 진입과 승인 출처/readiness 변경 미검출 2건을 찾아 수정했다. 각각 조기 return과 지문/필드 비교를 추가했고 실패 재현 검사를 통과시켰다. 감사자가 두 수정 위치만 다시 확인했으며 그 두 지적의 미해결 항목은 없다. 실제 사용자 UI 사건의 인증이나 모든 셸 동작의 차단을 helper 보장으로 주장하지 않는다.
