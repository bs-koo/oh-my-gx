## 실제 fixture 근거

helper 테스트는 임시 실제 파일과 subprocess를 사용한다. 모의 파일 시스템이나 구현과 같은 정규식의 복제 검사가 아니다.

- UTF-8 한글 경로·CRLF 파일의 실제 1-based 라인·SHA256 확인, 원본 내용/절대경로 미출력, 프로젝트 파일 내용·목록 불변.
- 파일 크기를 유지한 100→200 변경도 이전 지문과 달라 `changed`/exit 1. 같은 지문은 `valid`/exit 0.
- 없는 파일·0/역순/파일 밖/81줄 범위 거부.
- POSIX/Windows 절대경로·drive-relative·UNC·상위 경로 이탈 거부.
- 생성물·의존성·VCS·다른 worktree 상대경로 제외.
- 실제 파일 symlink와 외부 디렉토리 symlink를 거부. 이 실행에서 symlink 테스트는 skip 없이 통과했다.
- 바이너리/NUL·2MiB 초과 파일 거부.
- helper 하나를 공백·한글이 있는 별도 설치 캐시 위치에 복사하고 무관한 cwd에서 실행해 개발 저장소 import 없이 동작 확인.

문서 계약 테스트는 각 phase·마크다운 링크·정적 `Read()`가 해당 파일 위치에서 실제로 해석되는지, 읽기 전용·query 종료·의도/구현 구별·선택 위임·실패를 미확인으로 유지하는 계약에 두 하네스가 도달하는지 확인한다.

## 한계와 통합 인계

- 후속으로 새 문맥에서 새 스킬을 적용한 조회 probe 1회를 수행했다. 코드의 `<100`과 문서/테스트의 `≤100` 차이를 보고하고 운영 설정값·실제 호출은 미확인으로 남겼으며 아이디어 질문 없이 종료했다. 이는 임시 fixture의 새 스킬 1회 적용이며 구버전 A/B·실제 플러그인 설치 발견·모델 배정·질문 UI 검증이 아니다. 작성자의 자기검토 한계도 유지한다.
- probe에서 Windows 절대경로 앞에 불필요한 `/`를 붙이는 근거 링크를 발견해 SKILL 출력 지침을 보완했다. 설치 helper를 한글/공백 캐시 경로에 복사해 무관한 cwd에서 실행한 경로·라인·지문 및 잘못된 범위 거부도 확인했다.
- Windows junction/reparse point 거부 코드는 포함하지만 이번 fixture에서 별도 junction 생성은 하지 않았다. 실제 symlink 파일/디렉토리는 검증했다.
- helper는 파일·라인·지문의 호출 시점 검증이며 의미·실행 경로·운영 환경·동시 수정 잠금의 보증이 아니다. 프로젝트별 파서/SDK/의존성을 추가하지 않았다.
- 작업 지시에 따라 lens 한정 검사만 실행했다. 전체 저장소 린트·Codex 회귀·배포 리소스 검사, 최종 리뷰·커밋·PR 반영은 부모 통합 작업의 범위다.
