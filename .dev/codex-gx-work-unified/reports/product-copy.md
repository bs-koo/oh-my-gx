# 플러그인·스킬·공개 소개 문구 정비

공통 소개는 **도메인 컨텍스트와 TDD를 기반으로 개발 전 과정을 연결하는 AI 워크플로 오케스트레이션 플러그인**으로 통일했다. 수행 범위를 요구사항 분석·실행 계획·TDD·코드 리뷰·실행 증거 기반 검증으로 설명하고, 커밋·PR은 요청 범위에서 진행한다는 조건을 유지했다.

- Claude/Codex 플러그인과 marketplace, README, CLAUDE, Pages 설정·title·meta·hero·footer의 포지셔닝을 정리했다. 홈페이지 링크는 제품 소개 Pages로, 저장소 링크는 GitHub로 구분했다.
- 18개 스킬의 호출 조건과 역할을 간결하게 정리했다. 호출명·플래그·도구·권한·실행 게이트는 유지했다. 공통 진입/상태 조회·TDD 실행·단독 RGR·내부 헤드리스 역할을 구분했다.
- README와 Codex 가이드의 기본 설치·gx-work 시작·계획 전용·명시 PR 요청을 맞추고, 기존 제목 앵커와 로컬 링크 29개를 보존했다. 18개 스킬·17개 역할과 이전 버전의 실제 설치 17개를 구분했다.
- Pages의 스킬 카드·워크플로·명령 예시·FAQ를 현재 기능에 맞췄다. 모바일에서 긴 코드 예시가 문서 폭을 밀어내던 현상은 grid 자식의 최소 너비를 해제하는 CSS 한 줄과 설명 줄바꿈으로 보완했다. 설치 명령의 복사 내용은 바꾸지 않았다.

## 검증

YAML 18개와 메타데이터 JSON·사이트 설정을 확인했고 모든 SKILL 진입문은 UTF-8 LF 기준 20KB 미만이다. 기존 호출 설명/크기/자연어 라우팅 3개, context 계약 34개, 공개 문서·HTML 4개, 배포 이동·예산 4개와 생성물 검사도 통과했다. 문구에 고정된 구버전 테스트는 버전 일관성·필수 링크·접근성·호출 조건을 확인하도록 정리했다. 자동 계획 갱신은 설명에 중복하지 않고 기존 본문과 필수 마무리 계약 검사에 유지했다.

전체 정합성 검사에서 사이트 설명의 언어 중립 서술 누락 1건을 확인했다. `모든 언어 지원`이라는 포괄적 표현 대신 프로젝트별 설정에 따른 언어 중립 실행 절차로 명시하고 해당 조건을 재확인했다. 나머지 조건은 유지하며 원격 CI에서 최종 전체 정합성을 확인한다. 수정마다 전체 저장소 검사를 반복하지 않았다.

독립 검토자가 공개 설명과 실제 역할·게이트를 대조했다. 전용 임시 프로필의 headless Chrome으로 1440×1000 및 375×812 화면에서 가로 넘침·제목 잘림·앵커·FAQ·설치 명령 보존을 확인했다. 부모도 두 hero 이미지를 직접 확인했다. 로컬 결과와 화면은 `D:/Temp/gx-pages-copy-20261104/`에 보관하며 임시 브라우저·서버는 종료했다.

실제 플러그인 설치·모델 실행·외부 링크 전체 접속·Jekyll 빌드·공개 배포는 이 로컬 확인 범위에 포함되지 않는다. Pages 배포는 기존 workflow대로 main 병합 후 실행된다. 실제 토큰·시간 개선율도 측정하지 않았다.
