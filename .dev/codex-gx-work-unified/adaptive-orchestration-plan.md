# GX 역할을 유지하는 총괄 스킬

사용자 최종 지시: superpowers의 전체 고정 흐름을 복제하지 않는다. AI가 현재 요청·자료·진행 상태를 보고 필요한 GX 전문 스킬을 판단하고 결과와 다음 단계를 제안하며 실제 사용자 답으로 진행한다.

- gx-context: 도메인 문서·요구사항 원장·W작업 계획을 소유한다. 구체 구현계획을 새로 떠맡기지 않는다.
- gx-tdd: 기존 PRD·설계·T태스크 구현계획·RGR·리뷰·검증을 소유한다.
- gx-work: 의도 파악·전문 스킬 선택·최소 문서 준비·다음 단계 제안·사용자 응답·기존 작업 재개를 조율한다. context/lens/research를 모든 요청에 강제하지 않는다.
- 큰 개발 전환: 관련 결과와 W범위·종료점을 제시하고 TDD 진입 답을 받는다. 최초 일반 개발 요청은 이 질문의 답으로 승격하지 않는다.
- TDD 안 구체 계획 이후: 계획 검토와 현재 세션 중심/구현 서브에이전트 선택을 확인한 후 RGR로 진행한다. 기존 같은 run/계획의 실제 선택은 재사용한다.

확인한 superpowers 7.0.1에서 brainstorming은 의도·접근법·설계 승인, writing-plans는 구체 구현계획·자체 검토·실행방법 선택을 분리한다. GX에는 사용자의 단계별 결정과 전문 역할 분리 원칙을 적용하며 새 의존 플러그인이나 이중 설계/계획 체계를 만들지 않는다.

구현: request 또는 기존 plan 인계, 별도의 TDD 진입 응답/현재 범위 지문, 소비자 재검사, state 없는 질문 재개, TDD 내 계획/실행방법 연결을 보강한다. 기존 읽기 전용·보호 브랜치·verify·RED 격리·Ralph 명시 opt-in·요청 종료점을 유지한다.

검증: 실제 파일 helper 실패 재현→수정, 관련 스킬 계약, 마지막 독립 경계 조사, 통합 시 Codex 전체 계약 한 번·린트·생성물·최신 CI를 확인한다. 실제 설치 UI·모델 행동 검증은 별도다.
