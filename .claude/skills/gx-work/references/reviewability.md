# 판단과 검증을 검토 가능한 형태로 전달하기

계획 검토·스킬 간 인계·최종 결과를 제시할 때 적용한다. 별도 질문 단계나 새 보고서 양식을 추가하지 않고 기존 decisions·설계·Trust Ledger·검증 보고의 관련 항목을 재사용한다.

- **중요한 판단**: 동작·범위·정책·데이터 보존을 바꾸는 선택만 `선택 / 이유 / 핵심 가정 / 틀렸음을 확인할 조건 / 원문 위치`로 짧게 남긴다. 위임된 내부 선택은 승인 근거와 구분하고 일상적 결정을 전부 열거하지 않는다. 사용자 결정이 필요한 미정만 기존 질문 절차로 확인한다.
- **원문과 불확실성**: 자료의 경로·절/라인·요구사항 ID를 유지한다. 중요한 결론은 원문을 직접 열어 대조하고 원문이 바뀌거나 요약과 충돌하면 해당 범위만 다시 확인한다. 관측 사실·추정·미결정과 현재 구현·요구사항 의도를 구분한다. 후속 에이전트가 요약의 추정을 확정 사실로 승격하지 않게 하며 긴 원문 전체를 매번 복사하지 않는다.
- **검증 범위**: `무엇을 확인했는지 / 남은 중요한 미검증 조건 / 실제 명령·cwd·로그 위치`를 기존 증거에 연결한다. 테스트 통과를 운영 설정·배포·사용자 이해도까지의 보장으로 확대하지 않는다. AC의 실패 조건이 확인되지 않았으면 미검증으로 남기고 부족한 구체 조건에 필요한 focused 검사만 추가한다.
- **설명과 검토량**: 핵심 변경·중요한 판단·증거·미검증 사항부터 짧게 전달하고 상세는 원문 포인터로 연결한다. 동작 경계가 여럿이면 기존 W/T단위로 구분하며 새 문서에 중복 기록하지 않는다. 낯선 기술·정책의 선택 이유는 설명하고 학습 요청이면 이해 확인을 제공한다. 퀴즈·추가 승인·매번 새 리뷰 에이전트·전체 로그 출력은 기본 절차로 강제하지 않는다. 원본 증거에는 비밀값을 기록하거나 노출하지 않는다.

읽기 전용·문서 금지 요청에서는 판단과 차이를 대화에만 제시한다. 저장 권한, RED 격리, 기존 독립 리뷰·검증·사용자 승인 게이트를 바꾸지 않는다.
