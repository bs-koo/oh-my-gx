# Report: 현재 규칙과 확인 범위

오케스트레이터가 `EXPLORE_RESULT`를 합성한다. 먼저 `Read("../references/report-guide.md")`로 간결한 출력 형식을 확인한다. Explore에서 읽은 근거 계약은 다시 로드하지 않는다.

## 1. 근거를 유지하며 합성

- 질문의 직접 대상이 어떤 조건에 어떻게 되는지 결론부터 쓴다. R1… 규칙별 확인/추정/미확인 상태와 E1… 근거 위치를 유지한다.
- 관련 문서가 있으면 현재 구현과 의도를 대조한다. 문서 부재는 의도 미확인으로 쓴다. 모순·버그 의심을 정상 정책으로 번역하지 않는다.
- 상위 설정·관리 기능은 실제 대상 동작을 제어할 때 전제로 설명한다. 핵심 동작을 못 찾았다고 주변 기능을 대상 구현으로 승격하지 않는다.
- 별개 유사 기능은 요청 결과에 합치지 않는다. 혼동 가능성이 있으면 별도 한 줄로 차이만 적는다. 포함 여부를 일괄 질문하여 보고서를 지연하지 않는다.
- 근거가 바뀌었거나 위치가 유효하지 않으면 해당 구간만 다시 확인한다. 재확인할 수 없으면 상태를 낮추고 한계를 밝힌다.

## 2. 미발견·부분 결과

발견 0건이면 **조사한 경로·용어·예산 내에서 구현을 찾지 못했다**고 쓴다. 프로젝트 전체에 기능이 없다고 단정하지 않는다. 관련 문서가 있으면 문서상 의도만 별도로 보여준다. 확인 실패·이름 차이·동적 연결 중 실제로 남은 조사 경계를 적는다. 근거 없이 일반적인 원인 목록을 만들지 않는다.

부분 탐색은 확인된 결과를 먼저 보고하고 미확인 범위를 함께 적는다. 테스트·운영 실행을 하지 않았다는 한계를 짧게 표시한다.

## 3. 출력과 분기

보고서를 대화에 직접 출력한다. 파일을 저장하지 않는다.

- `IDEA_RAW`가 없으면 보고서를 출력하고 종료한다. 변경 아이디어 질문이나 `--idea` 사용 권유를 필수 마무리로 붙이지 않는다.
- `IDEA_RAW`가 있으면 `IDEA_CONTEXT = {idea: IDEA_RAW, clarifications: null}`로 두고 `Read("phase-impact.md")`로 진행한다.
- 후속 대화에서 사용자가 명시적으로 변경 아이디어를 제시하면 기존 포인터의 유효성을 확인한 뒤 Impact로 진행한다.
- 구현을 못 찾았어도 명시된 아이디어가 있으면 확인된 문서·부분 근거와 미확인 경계로 제한 분석한다. 자료가 전혀 없으면 영향 범위를 판단할 수 없다고 밝힌다.
