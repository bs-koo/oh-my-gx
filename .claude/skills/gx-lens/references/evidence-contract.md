# 규칙과 근거 계약

상대경로는 이 파일 위치 기준이다. 이 계약은 Explore에서 한 번 읽고 Report/Impact에서 같은 포인터를 재사용한다.

## 규칙 레코드

각 규칙은 다음 필드를 유지한다. 문서 부재·확인 실패도 빈칸 대신 명시한다.

| 필드 | 내용 |
|------|------|
| `rule_id` | 대화 내 안정적인 R1… ID. 후속 영향 항목에서 참조 |
| `status` | 확인 / 추정 / 미확인. 문장별 근거 강도가 다르면 나눔 |
| `observed` | 현재 코드에서 직접 읽은 조건·대상·결과. 근거 ID를 붙임 |
| `intended` | 관련 요구사항/도메인 문서의 규칙과 ID·근거. 없으면 의도 미확인. 명시적 사용자 결정은 해당 대화 발언을 출처로 표시 |
| `evidence` | E1… 근거 포인터 목록. 의도·구현·테스트의 종류를 구별 |
| `limits` | 확인하지 못한 연결·설정·운영값·예산 경계·문서 충돌 |

| 상태 | 사용 조건 |
|------|----------|
| 확인 | 직접 읽은 근거가 해당 주장 자체를 뒷받침함. 코드 확인이면 정적 구현에 한정하며 실제 호출·운영 실행을 뜻하지 않음 |
| 추정 | 직접 읽은 근거에서 해석·연결을 도출할 때 추가 가정이 필요함. 근거와 연결 가정을 함께 적음 |
| 미확인 | 근거 부재·접근 불가·미해결 동적 호출·운영 환경 등으로 판단 불가. 확인할 위치/조건을 적음 |

현재 구현을 의도된 정책으로 승격하지 않는다. 코드에 버그가 있을 수 있다. 의도 문서와 코드가 다르면 **현재 구현 / 문서상 의도 / 차이가 발생하는 조건**을 양쪽 근거와 함께 제시한다. 어느 쪽이 최신·승인 상태인지 불명확하면 그 판단을 미확인으로 남긴다. 파일명, 주석, 테스트 이름만으로 동작을 확정하지 않는다.

## 근거 포인터

`E1 = {kind, path, start, end, symbol, sha256?}`. `kind`는 구현/의도문서/테스트/설정. 사용자 대화가 출처면 파일 위치를 만들지 않고 발언 내용을 짧게 식별한다.

- 위치는 **프로젝트 루트 상대경로:시작라인-끝라인**, 라인은 1부터 시작한다. `src/purchase/limit.py:18-25`처럼 중복 파일명을 구별한다. 파일만 읽고 라인을 확인하지 않았으면 라인을 지어내지 말고 재확인하거나 미확인으로 둔다.
- `symbol`은 판정/참조 심볼 또는 문서 규칙 ID. 범위는 한 번에 최대 80줄이며 직접 읽은 관련 구간만 가리킨다.
- 숫자·단위·시간대·범위 포함 여부를 함께 기록한다. 설정 기본값은 운영값으로, 정적 참조는 실제 실행 경로로 단정하지 않는다.
- 테스트 근거는 기대 동작만 설명한다. 테스트는 실행하지 않았다고 명시한다.
- 보고서에는 업무 설명 뒤에 근거 ID와 파일:라인을 붙인다. 내부 레코드를 그대로 길게 출력할 필요는 없다.

## 작은 읽기 전용 확인 helper

근거 경로·라인 또는 후속 대화에서 재사용할 파일 지문을 반복 확인할 때 [check_evidence.py](../scripts/check_evidence.py)를 사용한다. Python 표준 라이브러리만 필요하다. 원본 파일 내용이나 보고서 파일을 출력·작성하지 않으며 정책의 의미를 판정하지 않는다.

설치된 gx-lens/SKILL.md 위치에서 `scripts/check_evidence.py`의 절대경로를 확인한다. 아래 `<설치된 helper 절대경로>`를 그 경로로 치환하고 소비 프로젝트를 `--project-root`에 명시한다. 셸 cwd를 설치 경로로 간주하지 않는다. Bash는 `python3`, Windows PowerShell은 `python`을 사용한다.

```text
python "<설치된 helper 절대경로>" --project-root "<현재 프로젝트 절대경로>" --path "src/purchase/limit.py" --start 18 --end 25
```

JSON의 `status`, `path`, `locator`, `sha256`를 확인한다. 파일 전체의 바이트 지문을 `sha256`으로 보관하고, 재사용 시 같은 명령에 `--expected-sha256 <이전 지문>`을 붙인다.

- exit 0 / `valid`: 현재 경로·라인 유효, 기존 지문을 준 경우 일치.
- exit 1 / `changed`: 파일 지문 변경. 이전 해석을 그대로 쓰지 말고 현재 구간·연결을 재확인한다. 다른 구간 변경도 탐지하므로 해당 규칙이 바뀌었다는 뜻은 아니다.
- exit 2 / `invalid`: 경로 이탈·제외/링크 경유·읽기 불가·라인 오류 등. `reason`을 확인하고 근거로 사용하지 않는다.

helper는 루트 아래 링크·제외 경로, UTF-8이 아닌 파일·NUL 포함 파일, 2MiB 초과 파일, 80줄 초과 구간을 거부한다. 이 경우 허용 범위 안의 읽기 도구로 필요한 구간을 확인하거나 미확인으로 남기며 파서·SDK를 설치하지 않는다. 민감한 설정 원문을 보고서에 붙이지 않는다.

검사는 호출 시점의 파일 상태다. 동시 수정에 대한 잠금이나 완전한 보안 경계를 제공하지 않는다. 중요한 근거를 출력할 때 변경 징후가 있으면 다시 확인한다. 문법/타입/호출의 정확성, 실제 환경값, 실행 성공, 보안·법적 준수는 검증하지 않는다.
