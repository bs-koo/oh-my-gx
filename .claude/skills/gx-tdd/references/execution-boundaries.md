# 실행 종료점과 Git 부수효과

작업 계획의 착수·재개·되돌림·완료 기록과 context 동기화도 동일한 종료점을 따른다. setup-work, setup-resume, phase-complete가 이 계약을 사용한다.

| stop-at | 로컬 문서/코드·검증 | 커밋 | 원격 push·PR |
|---|---|---|---|
| understand / plan | 요청한 이해·계획만 | 하지 않음 | 하지 않음 |
| verify | 구현·관련 검증·로컬 계획 상태 갱신 | 하지 않음 | 하지 않음 |
| commit | 검증 및 로컬 커밋 | 허용된 범위만 | 하지 않음 |
| pr | 검증·커밋·PR | 허용된 범위만 | 요청 범위에서 수행 |

종료점이 없는 구 세션은 보존된 사용자 요청에서 복원하고, 근거 없이 commit/pr로 확대하지 않는다. 별도의 명시적 원격 반영 요청이 있다면 그 실제 결정 근거를 기록한다. 반복적인 동일 승인 질문은 하지 않는다.

verify에서 작업 계획 행은 로컬로 수정하고 미공유 상태임을 알린다. commit에서는 `.dev/plan.md`만 별도 커밋할 수 있으나 push는 하지 않는다. pr에서는 현재 작업 브랜치로 `git push -u origin <branch>`할 수 있으며 베이스 브랜치로 보내지 않는다. 미공유 상태에서는 다른 팀원이 원격 착수를 확인할 수 없음을 알려 중복 작업 위험을 드러낸다.
