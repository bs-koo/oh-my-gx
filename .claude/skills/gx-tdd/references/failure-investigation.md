# 실패를 수정하기 전의 조사

focused 테스트 실패·빌드 실패·반복 수정이 발생했을 때 읽는다. 정체 복구 역할을 부르기 전에 조정자가 아래 근거를 모은다.

1. 실패 명령·exit code·관련 로그 위치·재현 조건을 기록한다. 러너 미설치·옵션 오류·0건 실행은 제품 결함과 구분한다.
2. 최근 변경과 실패 지점을 비교한다. 외부 연동이면 어느 경계에서 입력·출력이 달라졌는지 확인한다. 민감 값은 로그에 새로 노출하지 않는다.
3. 원인 가설 하나와 그 근거를 적고 가장 작은 실험으로 확인한다. 서로 다른 수정을 한꺼번에 쌓거나 같은 전체 테스트를 반복하지 않는다.
4. 실제 결함이면 실패하는 재현 테스트부터 수정한다. RED 작성자는 기존 프로덕션 코드 미열람 계약을 유지하고, 조정자가 제공한 재현 조건·인터페이스만 받는다.
5. 같은 가설이 반복 실패하면 새로운 증거로 원인을 재검토한다. fix 4~5의 격상과 총 5회 상한은 유지하고 매 라운드 phase-implement의 fix loop 절을 다시 읽는다. 설계 결함이면 architect에 근거를 전달한다.

결과는 현재 report에 `가설 / 실험 / 관찰 / 다음 판단` 네 항목으로 append한다. 근거 없는 '아마 해결'을 완료 증거로 쓰지 않는다.
