# 리뷰에서 근거가 부족할 때

태스크/전체 리뷰가 `❓ 확인 불가`, `ac_unverified`, `unverified_ids`를 보고했을 때만 읽는다.

1. AC와 reviewer가 필요한 근거를 확인한다. 변경하지 않은 기존 코드·다른 태스크에 구현돼 있을 수 있으므로 현재 diff에 없다는 사실만으로 미구현이라고 판단하지 않는다.
2. 조정자가 해당 파일의 필요한 절·기존 테스트·승인된 결정만 읽고 reviewer에 경로와 범위를 보강한다. 테스트 실행이 필요한 구체적 의심이면 관련 focused 명령만 실행한다. 같은 코드의 동일 증거는 공통 테스트 계약으로 확인한다.
3. 보강된 항목만 scoped 재리뷰한다. 실제 동작 결함이면 RED 재현 후 수정, 이미 충족하면 근거와 함께 통과로 정정한다. 구현자 자기보고만으로 통과시키지 않는다.
4. 요구사항 자체가 부족하면 product-owner에 해당 AC만 보강하도록 요청한다. 사용자가 결정해야 하는 내용만 질문하고 기존 승인·설명은 반복하지 않는다.
5. 여전히 확인할 수 없으면 완료를 보류하고 필요한 근거를 명시한다. 확인 불가를 PASS로 바꾸거나, 확인 불가만으로 재구현 라운드를 소모하지 않는다.
