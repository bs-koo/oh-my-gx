# 개발 작업 규칙

1. **요청과 기존 상태 확인**: 새 작업은 gx-work로 목적·기존 자료·종료점을 정리하고, 진행 중인 TDD는 기존 상태를 복원한다. 사용자가 지정한 스킬과 범위를 우선한다.
2. **필요한 context만 참조**: 관련 `context/{도메인}`이 있으면 필요한 용어·정책·구조·미반영 요구사항을 읽는다. context가 없다는 이유만으로 전체 도메인 등록을 강제하지 않는다. 일회성 변경은 작업 명세와 원문 포인터로 충분하다.
3. **기존 결정 재사용**: 유효한 요구사항·설계·계획과 실제 승인 근거를 재사용한다. 결과·범위·위험을 바꾸는 미결정과 충돌만 확인한다. 반복 사용할 정책·용어가 달라지면 해당 context를 갱신하고 수정일을 기록한다.
4. **TDD로 실행·영향 범위 검증**: RED 선행·테스트 불변·verify 지문을 유지한다. 테스트는 승인된 소유권과 실제 변경으로 고르고 동일 실행의 검증된 증거만 재사용한다. 명시적 전체 검사·공통 설정·의존성·범위 불명확만 전체로 확대한다.
5. **종료점 준수**: 계획만 요청하면 실행 setup을 하지 않는다. 기본은 검증까지이며 커밋·원격 push·PR은 실제 요청한 범위에서만 수행한다. 관련 원장·계획 상태는 부분 구현을 완료로 바꾸지 않고 근거에 맞게 갱신한다.
